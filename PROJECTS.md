## 1. Link City

**What it is.** The one link to everything. A launcher page you add to your phone's home screen like an app. It lists every project with its icon, a banner, a Public/Personal tag, when it was last pushed and how many commits it has.

**How it works.** A single static `index.html` reads `projects.js`, a hand-edited array of `{ repo, name, audience, live, icon }`. When the page opens it asks the GitHub API for each repo's last push, commit count and homepage, and caches the answers for 3 hours ("Counting commits 9/36"). There are two views. **Cards** are wide, compact cards with real banners. **Links** is a master list with a Copy button per row and Copy all. Sorts are Recent and Most work, filters are All/Public/Personal, and there's a search box. Every entry links to its live GitHub Pages site, not the repo.

**Tech.** Vanilla HTML/CSS/JS, `.nojekyll`, web manifest, an icon set in `icons/`. No build.

**History.** Built in one day (20 Oct 2026, 14 commits): hub, then banners and tags, then the Links view, then icons for every app, then Link City added to its own list.

**State.** Live at https://seanjoudrie.github.io/LinkCity/. It's one of the few repos still under the old `SeanJoudrie` name. This file (`PROJECTS.md`) is its reference companion.

## 2. Codex

**What it is.** A personal, self-refreshing **visual index of GitHub**: animation, shaders, simulations, game AI, algorithms, procedural generation, data viz, "anything worth stealing an idea from." Every repo gets a screenshot. It's an inspiration library, not a curated recommendation list. Everything goes in, the licence shows as a tag, and you decide later what's worth building on.

**How it works.** A five-step pipeline run by a daily GitHub Action ("Refresh", 09:00 UTC):
1. **Discover.** Pulls candidates from 91 seed repos (from a "Creative-Coding Experiments Master Doc"), awesome-lists, GitHub topics, search queries and followed people, both their repos and their stars.
2. **Enrich.** Adds stars, language, licence, homepage/demo, topics and the first README image.
3. **Capture.** Makes one 600px WebP per repo. The preferred source is a live demo screenshot (WebGL rendered on CPU via SwiftShader), then a README image or GIF, then GitHub's social card.
4. **Tag.** Roadmap: an LLM one-line technique summary plus categories.
5. **Build.** Produces a static site with a grid, search, 26 category filter chips and ★ favourites.

Up to 250 new repos a day, plus a fresh discovery sweep every Monday. The index holds **9,112 entries**.

**The idea generator** (`site/ideas.html`) turns the archive into project ideas. You pick what you're making (game, art piece, app, portfolio piece, website, tool), answer follow-ups, and choose how many "building blocks" to combine (2–10). Each idea lists its blocks with archive references and a "make it yours" prompt. You lock the blocks you like, swap the rest, and copy the idea as a Claude prompt. **"Pay the bills" mode** adds a money plan to each idea (price, who pays, free vs paid, user sources, users needed for a monthly goal, risks) and scores it on willingness to pay, demand, niche, reach and recurring income.

**Slime Sculpture** (`site/slime/`) is the first thing built from the archive: a physarum slime-mold simulation (Jones 2010, after `nicoptere/physarum`) that runs across the surface of a 3D model instead of a flat image. You can upload `.glb/.obj/.stl`, pick a colour and click to plant spores.

**Working rule (CLAUDE.md).** When the owner describes an idea, run `npm run ideas -- "<idea>"` and pull references *before* giving advice. There's also `prompts/scout.md`, a web-search prompt for hunting already-built flashy projects across all 26 categories.

**Tech.** Node scripts, Playwright, sharp, GitHub Actions, static site on Pages.

**State.** Live at https://joudrie.github.io/Codex/ (and /slime/). 63 commits, 24 Sep – 9 Nov, still being worked on.

## 3. Job

**What it is.** A personal job scanner that runs on rules you write and can read, instead of a feed that decides what you're allowed to see. The repo is public by the owner's choice. `PROFILE.md` holds the personal half (constraints, fit reasoning, résumé strategy) and `SPEC.md` holds the machine.

**The design ideas, each a deliberate stance:**
- **Logistics outrank industry.** Pay, commute, posture and hours carry 60% of fit, and what the job is carries 40%. A Tier C role at $28/hr twenty minutes away beats a Tier A role at $21/hr in Boston.
- **Lanes, not one list.** A bridge job and a career job are optimized against different things.
- **Commute in minutes, not miles.** A mile radius had let a 50-minute drive through.
- **A visible funnel.** Every rule shows how many jobs it removed, and switching one off brings them back.
- **Soft vs hard requirements.** "Bachelor's preferred, 5 years or equivalent" is reported as *open*, because self-selecting out of soft requirements loses more jobs than any filter.
- **Clearance eligibility counts as met.** "Must be able to obtain a Secret" is satisfied by a citizen in the Guard.
- **An applied log that survives everything,** and **dead reqs named**: a job you applied to that reappears as "new" is recorded as a dead req.
- **USAJOBS** support (optional free key), where Guard service and veteran preference are actually scored.

**Privacy split.** Only `data/history.json` (first-seen dates and repost counts, the one thing that can't be refetched) is committed. The applied log, cover letters, API key and settings stay in the browser. Scoring and letter-writing run on-device with your own Anthropic key.

**Tech.** React + Vite + Tailwind + TypeScript, `@anthropic-ai/sdk`, Playwright e2e, **321 unit tests**, `npm run audit` (measures the scoring model against the real pool), a nightly scan action.

**History.** The spec started inside Todo (28 Aug) and moved to its own repo the same day. "Spec only, nothing built yet, by request" came first, then the build. 87 commits. The nightly "Posting history" commits run through 10 Nov.

**State.** Live and scanning nightly.

## 4. Pulse

**What it is.** A daily trend tracker for Roblox games: who's playing, who's growing and roughly who's earning, over a day, week, month, 3, 6 or 12 months.

**How it works.** `collect.mjs` reads Roblox's own public charts (Top Earning, Up-and-Coming, Top Trending, per-genre trending and more). For every game on them it records players online, visits, favorites and votes, and appends a snapshot to `data/days/YYYY-MM-DD.json`. `build.mjs` turns the daily files into per-range leaderboards, genre shares, a platform-wide line and one history file per game. Games stay tracked for 30 days after they drop off every chart, so their lines don't just stop. It rides out Roblox rate limits instead of failing.

**Revenue is an estimate,** and labelled as one: new visits × 0.02 × 150 Robux × 70% × $0.0038 (Profitable.app's published formula), shown beside Roblox's own Top Earning chart as a real, amount-free signal. History starts on the first run. Until it fills in, each game links out to RoTrends, RoMonitor, RoWatcher and Profitable.app.

**Tech.** Node 20, zero dependencies, GitHub Actions daily at 20:17 UTC, static site on Pages.

**State.** Live, with daily snapshots from 9 Oct through today (37 commits, mostly snapshots).

## 5. College Culture

**What it is.** What colleges are actually like, written for high schoolers. It isn't rankings and it isn't advice. Each school page covers the vibe, social life, getting in, stereotypes vs. reality, myths, and who it's a good fit for, based on what students and alumni say. The focus is New England.

**What's on it.** **128 school pages**, all built from one template, each school being one data file of content plus colours. There's a **Find Your Fit quiz**, a **Compare** page (two schools side by side, `compare.html#a=<id>&b=<id>`), a **Basics** page (a timeline from junior year to move-in, common myths, campus-visit tips) and a **Glossary** of college words in plain English. Undergrad size, admit rate and "What it costs" come from the federal **College Scorecard**, not the school files.

**Design system.** The header band uses each school's colours, with contrast-checked accents (bright school colours go on the stripe and a darker shade becomes the accent). There's one font (Archivo), with optional `classic` (Libre Caslon) for old traditional schools and `slab` (Roboto Slab) for tech, maritime and military schools. Text sizes are 13/15/17 plus display, spacing is on an 8pt scale, there's one 4px radius and no decorative animation. Fixed **vibe meters** (party scene, campus feel, school spirit, academic pressure, career focus, Greek life, religion) rate every school on the same scale and feed the quiz. Generated `s/<id>/` pages give every school a real URL and link-preview image.

**Tooling.** `check-schools.js` lints every school file for colours, contrast and content rules. Separate tools rebuild the quiz data, Scorecard stats, pages and OG images.

**History.** It started as a Northeastern prototype page, which became the template, then SNHU, UConn and UVM. 64 commits over 15–20 Oct. A top-20 fact check was done. The README says content is approximate as of 2026 and needs checking before anything goes fully public.

**State.** Live.

## 6. Teris (Tumbledown)

**What it is.** "Fire, water, ice and stone: a falling-block puzzle where every piece is a material with its own physics." You put materials next to what cancels them, set off chain reactions, fill the goal before your pieces run out, and climb down a **100-floor tower** from the clouds to the ground. Internal code name: Material Blocks (save keys `mb_*`).

**Mechanics.** Each level has a **piece budget** ("fill the bar in N pieces"), which is the biggest design change. There are material interactions (glass and brick blocks, fire blocks), combos, powers, and a **Sand mode** (coloured clay sand: link one colour wall to wall to clear, with corner-touching grains counting as connected). There are crate gifts, crumbling floors and stone audio.

**Presentation.** A full "Toybox" redesign rebuilt the presentation layer to studio quality while leaving the rules engine (`core.js`, `session.js`, `levels.js`, `scenes.js`, `validate.js`) byte-for-byte unchanged. It includes:
- a voxel block renderer
- drain flights into the goal and a new HUD
- the tower map, win/lose screens, pause, settings, shop, daily gifts, codex and level intro cards
- stars, coins, boosters, gifts and skins
- a procedural audio engine with generative music

There was also a "Quarry" UI direction built from the game's own blocks. A **UI fingerprint audit** compared it against Cartopia to strip out the default AI-shared look.

**Monetization.** An ad flow is built in (`src/ads.js`, "pixel material game with combos, powers and ad flow").

**Quality bar.** Every number in `DESIGN.md` comes from a re-runnable script: 123/123 unit tests, 14/14 hook checks, 40/40 card scenes, 35/36 mobile browser checks. Content-hashed URLs plus a version check mean players always get the latest build.

**Working rule.** Ship every finished task to the live site without asking, because the owner texts the link to friends after each update. Pages builds from `claude/new-session-qpcuho`.

**History.** 59 commits in two days (14–15 Oct).

**State.** Live at https://joudrie.github.io/teris/.

## 7. Baby Name (Cradle)

**What it is.** A calm, swipe-to-sort baby name finder. Swipe right to keep a name, left to pass, up if you're not sure. The working name is Cradle, set in one config line so a rename is trivial.

**Features.**
- Country decks and a fiction deck.
- Card flip for details: origin, meaning, pronunciation, nicknames, an initials check.
- Undo and history.
- **Boxes** rebuilt as folders with tiers, quick remove with undo, no emojis.
- **Partner compare**: a box is packed into the link's `#hash`, so there are no accounts and no server.
- An accent-aware letter filter.
- Home-screen app and offline service worker.
- One SEO page per name plus an A–Z index and sitemap.
- Ads and legal pages.

**Data.** US Social Security names 1880–2024 with origin, meaning and pronunciation (MIT `usbabynames`). Official statistics from England & Wales (ONS), Ireland (CSO), France (INSEE), Spain (INE), Norway (SSB) and Scotland (NRS 2024–25). About 8,900 more names from Wiktionary for thin decks (Nigerian, Turkish, Indian, Japanese, Chinese, Korean). Hand-picked Igbo names with meanings.

**Engineering note.** The swipe engine writes drag transforms straight to the DOM (no React render per frame) and flies cards out with the Web Animations API, so the next card is usable immediately.

**History.** Phases 1–4 and all the data work happened in a single day (14 Oct), 14 commits on the `claude/baby-name-swiper-sdubqr` branch. `main` holds only the initial commit.

**State.** Live at https://joudrie.github.io/babyname/.

## 8. WordUp

**What it is.** Type any English word and see where it came from: its family line, how far back it goes, its first recorded use and the words it's related to. The name is a working name. It's built on the same stack as Globalio and is meant to cross-link with Globalio and Reign.

**What's built (Phase 1, "Look it up").**
- Live search on every keystroke, plus "contains" search (`eau` finds *beautiful*).
- Word pages with a hook, parts, ancient root, family line, first recorded use (the earliest dated Wiktionary quotation, with source), relatives, pattern callouts, lookalikes, sources, a confidence label and a **myth badge**.
- A homograph picker for spellings with several unrelated origins.
- **Explore**: 21 origin sections, Proto-Indo-European roots, prefixes and suffixes, spelling patterns, slang and internet words, a sentence lab, Old English to modern, word stories.
- **Play**: a daily word game with no length shown, where hints teach the word's language and roots.
- **Today**: word and story of the day.
- **Journeys** (newest, 9 Nov): a feed where you swipe through each step of a word's travels across a map, with the dotted line drawing itself.

**Data.** **478,535 generated entries** from the kaikki.org Wiktionary dumps (about 3 GB), with ancestor chains through Latin, Old/Middle English, Old French, Old Norse, Ancient Greek, Arabic and the proto-languages. Frequency ranks come from FrequencyWords en_50k, and hand-checked entries in `content/curated-words.json` override the drafts. It's CC BY-SA, and the README is explicit that Etymonline and the OED must not be copied or scraped.

**Honest gaps (from the README).** Every generated entry is still a draft. Known bad chains include *algorithm* never reaching Arabic. The top ~1,000 words need human review before launch, plus about 50 hand-written stories, Reddit feedback, and a decision on brand colour and domain.

**State.** Live, Phase 1 in progress. 21 commits, 8 Oct – 9 Nov.

## 11. Reign

**What it is.** A swipeable history of each country's rulers, told as one continuous drama. The working title will change.

**Content model.** One JSON file per country, **49 decks** (England, France, Byzantium, the Abbasids, the Mughals, China, Japan, Korea, Ethiopia, Egypt, Hawaii, the Holy Roman Empire, Liechtenstein, Monaco and more). The schema is in `src/data/schema.ts` (zod). A **ruler** is a person and a **reign** is one card in swipe order. Co-monarchs share a card, a civil war is two overlapping reigns linked by `contestedWith`, and gaps are `interregnum`. `npm run validate` checks for impossible dates, unmarked overlaps, dangling ids and missing hooks.

**Rules.** Write in our own voice, never paraphrased Wikipedia. Wikimedia Commons images only, with credit and licence. Nothing is marked `checked` until a human has verified every name and date.

**Features in the prototype.** The card deck in a "Vellum" palette, quick stats and recaps, a quiz, a **Fates** bar chart (how reigns ended), a compare row, real flags, a **heraldry pilot** (house pages with coats of arms through time), England extended with 18 Anglo-Saxon and Danish kings, landscape layout, an offline service worker, and a joke "Westeros" deck listed under every region tab. Portrait sheets live on the `gh-pages` branch.

**History.** **209 commits**, 2–27 Oct, including content-review passes across 27 decks and a release review.

**State.** Live at https://joudrie.github.io/reign/.

## 12. Game

**What it is.** A mobile-first third-person action game in three.js. The feel draws on GTA / Red Dead / Watch Dogs / Assassin's Creed, with Lego Star Wars fun. The one-line vision is **"Hitman, but loud."** You're with **the Vanguard**, you drop into a mission on a planet, and you can do it quietly and perfectly or blow the whole base up. Play solo or duo co-op.

**The owner's "best five minutes."** A friend is the Jedi and you're the guy with the gun. The stealth goes well, then the Jedi pushes when he meant to pull, knocks a guard into an exploding barrel, the base goes on alert, and it all goes wrong in a fun way. Every mission should be able to produce that moment.

**Ground rules (VISION.md).** Modern Warfare 2–serious guns with over-the-top, flash-game consequences. Dismemberment that isn't graphic or cruel. Faceless enemies. Dying is no big deal (fast respawn). Over-the-top score popups and a trophy for a perfect stealth run. A loose, silly story chain (a rogue military allying with an evil faction on each planet). The *Wake* universe's planets and tech, used loosely. Characters are inspired by the owner's custom Lego figures but built realistic, so nothing should look like Lego.

**What's built (v52).**
- Three classes with sprint, slide and double jump.
- Saber combat modelled on Jedi: Survivor: five-hit combo, a heavy combo, four dual-saber combos, block and parry, saber duels with guard breaks.
- Force push, pull, choke, lightning and saber throw.
- A dismemberment system: the blade cuts where it passes, a cut leg makes an enemy crawl.
- Guns, grenades, a jetpack, five enemy body types mixed per squad.
- A **Moves** screen for previewing and picking animation variants.
- An in-game watchdog that reports T-poses and freezes.
- A phone LITE mode with a thumb-corner pad, and a loading screen that names each step and offers copyable diagnostics.

**Asset pipeline.** `tools/retarget.mjs` maps any T-posed humanoid clip (Mixamo, BVH mocap, UE rigs) onto the game skeleton. Bakers handle Mixamo, 100STYLE mocap, CMU flips and Mesh2Motion. The playable build is a single ~14.5 MB `dist/index.html`. **Standing rule: no Claude-made 3D models.** Every model is downloaded, licensed and credited ("find, don't build"). A headless audit suite covers controls, perf and bug hunts.

**Docs.** VISION, PLAN, a 38 KB BACKLOG, an 82 KB CHANGELOG, IDEAS (everything the owner has liked from other games, with build status), ASSET_GUIDE and CREDITS.

**History.** **160 commits** and 67 PRs, 29 Sep – 3 Oct, so v1 to v52 in five days.

**State.** Playable prototype at https://joudrie.github.io/Game/.

## 24. OCS Survey (OCS Billet Rotation)

**What it is.** A single-file web app that schedules platoon leadership and staff billets across a **12-month OCS Phase II cycle**. Ten candidates submit availability. A solver assigns Platoon Leader and Platoon Sergeant, and the rest fill S1–S6 each month.

**The algorithm.** Candidates sit on a wheel of N. In month *m*, PL = `wheel[m % N]` and PSG = `wheel[(m + ⌊N/2⌋) % N]`, so a person's two turns land half a cycle apart (five months at N = 10). It **hill-climbs over seat permutations with 220 random restarts**, scoring hard-blocked months +1000, soft-avoid +25 and preferred −8. Hard blocks are weighted 40× so they're only violated when unavoidable, and the overlap is reported. The staff shops are filled greedily: +4 for a top-3 pick, +3 for experience, −6 for an avoided shop, −3 for a hard-blocked month, −3 per prior tour in that shop. Leftovers float.

**Storage.** Supabase over raw PostgREST `fetch` with no client library, in three tables (responses keyed by name slug, so resubmitting upserts; config; the saved schedule). The schedule is stored by slug, not array index, so roster edits don't scramble it.

## 26. Color (Colorbook)

**What it is.** Turns a phone photo into a coloring page, then lets you fill it with a paint bucket. Everything runs on-device in a Web Worker, with no upload and no backend.

**The key insight (from the build prompt).** "Derive the lines from the regions, not the regions from the lines." Edge detection gives open contours with gaps, so fills leak, which is the #1 complaint in the category. Segmenting into regions first makes every area closed by construction.

**Pipeline.**
1. EXIF-aware decode and downscale to 1400px.
2. Median smoothing on RGB (a 19-comparison sorting network).
3. CIELAB with **lightness weighted 0.4**, so shadows and wrinkles don't become lines.
4. A Sobel gradient on true luma, k-means++ quantization, a majority filter and union-find labelling.
5. **Edge-aware merging**: regions merge only if colours are close *and* the border isn't a real edge, thresholded on the photo's own gradient percentile, which is what keeps eyes and lips from dissolving.
6. Lines = region boundaries.

A five-level Detail slider is cached per level. A debug "stained glass" region map shows leaks. An **AI lines mode** uses the Informative Drawings model.

**History.** 8 commits, 5–6 Aug. The first architecture was built, failed, and the prompt was rewritten around the corrected one.

**State.** Step 1 (photo to line art) is built. Step 2 (tap-to-fill) isn't.

## 29. DroneDome

**What it is.** "Build a drone out of real aircraft, then find out whether it flies."   - Breguet range and endurance (the aircraft gets lighter as it burns)

- `check:physics` compares every preset against published figures, and all land within 2× except Ingenuity (battery-heat limited).

## 33. Curio

Moods, boosts and a wildcard, achievements, sketches, a daily treasure-chest ritual, curated hero photos for all 17 drawers, export, onboarding, haptics. ESLint, tests, CI and hardening for crash resilience and data safety.

**History.** 42 commits, 4–6 Jul: spec, then a working PWA the same day.

## 34. REX

**What it is.** A swipe-based movie and TV picker. Swipe right to save, left to pass, up for watched. Every swipe teaches it your taste. The point is to **pick something in a couple of minutes and go watch it**, not doomscroll a catalog.

**Three product bets.**
1. **Decide fast, then leave.** Success is the exit, and it nudges you out with "you've got something for tonight."
2. **Show people themselves.** The **Mirror** turns your swipes into a shareable taste portrait, the word-of-mouth loop discovery apps lack.
3. **Decide together.** Multiplayer **Match** modes: pass-the-phone, blend, and **live two-phone Tinder-style matching**.

**Features.**
- A velocity-aware swipe deck with stamps, haptic grammar and undo (it reverses the taste change too).
- A bottomless auto-paginating deck.
- Sorts: Popular, Top Rated, Box Office, Newest, New on Streaming, Hidden Gems.
- Genre, year, streaming-service filters with normalized provider names, and actor search.
- "A tag is just a query": tap any actor, director, studio or keyword to get a single-entity deck ("an A24 deck").
- "Because you like…" provenance.
- A learning engine v2 with entity affinity, value-matrix weights and decay.
- A cute bipedal T-rex mascot.

**Tech.** React + Vite + Tailwind PWA, live TMDB data through a Supabase Edge Function proxy, guest mode on-device, optional cloud backup.

**History.** 46 commits, 20–23 Jun.

**State.** Live.

## 35. Drinky (Rap Sheet)

**History.** 8 commits, 17–18 Jun.

## Across the whole body of work

These are facts read off the 36 entries, laid out for later analysis of strengths and habits. They're observations, not verdicts.

### Volume and pace
- **About 4,645 commits across 33 readable repos** between 2 May and 11 Nov 2026 (about six months).
- **Where the time went:** Flexyn alone is 2,432 commits (52%). Globalio (481), Lego (333), Reign (209), the portfolio monorepo (173) and Game (160) are the next tier. Together these six are about 82% of all commits.
- **Most projects are built in one to four days.** Teris, Baby Name, Boot, OCS Survey, FlexChex, Color, Eventr, Drinky, Curio, REX, Sled, DroneDome, Birb and AAR all went from first commit to working build in that window.
- **The ones that kept going for weeks or months** are Flexyn, Globalio, Lego, Reign, Codex, Job, WordUp and Pulse. All of them are either a product with real users (Flexyn, Globalio), a growing body of content (Lego, Reign, WordUp, Wake), or something that runs itself on a schedule (Codex, Job, Pulse).

### What the projects are about
- **Games and play** (9): Globalio, Teris, Game, Sled, DroneDome, Drinky, Song Guess, ConnecSeans, JJ.
- **Reference and knowledge archives** (7): WordUp, Reign, College Culture, Wake, Lego, Codex, Birb.
- **Personal tools built for one user** (8): Todo, Job, Stool, Dream, Boot, OCS Survey, FlexChex, Giveaway.
- **Anti-doomscroll and "decide, then leave"** (4): REX, Curio, Algorithm Builder, Eventr. Each one measures success by the user leaving the app.
- **Military to civilian** (4): AAR, Job (clearance and USAJOBS scoring), OCS Survey, Boot.
- **Fitness** (3): Flexyn, Flexyn v1, FlexChex.
- **Craft and design studies** (3): Craft/Friendspace (dark patterns), Color (image processing), the portfolio's Range demos.

### Habits that repeat across repos
- **Spec before code.** Curio, Eventr, Dream, Job, Todo, Color and Wake all have a full written spec or build prompt first, often with explicit **non-goals** and a **REJECTED** list.
- **Restraint as the thesis.** Stool cut itself back to "a poop journal" on day two. Dream is "a dream journal, that is the entire product." Todo is "not a product." Curio is "one confident pick, not a stream."
- **No accounts, no server, state in the link.** ConnecSeans, Sled, Baby Name's partner compare, Algorithm Builder's check-back link and Dream's sync code all avoid sign-up. Stool makes zero network requests after load.
- **Honesty about data.** Pulse labels revenue as an estimate and gives the formula. Birb refuses to call its index a percentage. WordUp marks every entry a draft and lists known bad chains. Boot's build fails if a quote isn't really on its page. Reign won't mark a deck checked until a human verifies it. DroneDome compares itself against published figures.
- **Real-world data pipelines.** GBIF and eBird (Birb), Wiktionary dumps (WordUp, Baby Name), the College Scorecard, Roblox charts, TMDB, Library of Congress maps, NASA and Sketchfab models, Social Security and national name statistics.
- **An anti-"vibe-coded" design standard.** It's written down in the portfolio's CLAUDE.md and recurs as "remove the tells" passes in Dream, Stool, Eventr and Teris (the UI fingerprint audit).
- **Audits as a working tool.** Flexyn (19 findings documents), Curio (two scored audits), Dream (a 63 KB audit), Game (an automated bug-hunt suite), the portfolio (audit, gap analysis, motion audit), Globalio (AdSense audits).
- **Ship to the live link, every time.** Teris, Baby Name, Todo, Globalio, College Culture and the portfolio all carry a standing rule to deploy every finished change, never send artifacts or branch links, and confirm the live site.

### Where things stop
- **Prototype, not finished:** Eventr (app built, never launched), Birb (data and prototype only), Color (step 1 of 2), Sled (no stamp placement or rider parts), Giveaway (guide only), WordUp (drafts awaiting review), Game (prototype at v52, last change 3 Oct).
- **Empty `main` with the work on a branch:** FlexChex, OCS Survey, Baby Name, Color and Craft. The real code sits on `claude/...` branches, and the live sites build from them.
